## When to use it

Use gradient boosting when you want an ensemble of trees that can run as classification or as regression from one dialog. Mode starts at classification. Random forest is the bagged counterpart: [classification](/docs/analyses/random-forest-classification) or [regression](/docs/analyses/random-forest-regression).

## Assumptions

Classification: categorical outcome, numeric features, classes with fewer than two rows dropped. Regression: numeric outcome. Holdout fraction 0.25, 100 trees. Chat dispatch does not forward `test_fraction`. Learning rate and maximum depth are not exposed.

## Running it in Tensr

<Steps>
<Step>ML → Classification → Gradient Boosting (Classification), or ML → Regression → Gradient Boosting (Regression). In chat: “Gradient boosting of passed on hours and anxiety.”</Step>
<Step>Set mode to classification or regression. Target matches that mode. Features need at least one numeric column.</Step>
</Steps>

## Reading the output

The same pass/fail outcome, classification mode, 100 stages, 25% holdout.

| Actual \ Predicted | 0 | 1 |
| ---: | ---: | ---: |
| 0 | 7 | 5 |
| 1 | 5 | 7 |

| Variable | Importance |
| --- | ---: |
| hours | 0.484 |
| anxiety | 0.516 |

Train accuracy = 1, test accuracy = 0.583, n = 96. Hours only shifts the pass rate a little, so a large gap between train and test is overfitting, and a test accuracy near 0.5 is chance.

## Reporting (APA 7)

Holdout classification of `passed` from hours and anxiety, n = 96. Test accuracy = 0.583, train accuracy = 1.

## Coming from SPSS

SPSS has no gradient-boosting dialog. Tensr puts classification and regression on the ML menu as two labels of this one procedure. The path string stored for this item says ML → Gradient Boosting.
